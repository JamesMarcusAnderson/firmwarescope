What it does

Point it at a firmware image. It scans the image and writes an HTML report you can read and share. Version 1.0.0.

Firmware triage

Identifies the image format and chip family, maps ELF sections (32-bit and 64-bit), and extracts readable strings, so you know what you are looking at before you dig deeper.

Vulnerability-pattern flagging

Flags risky patterns in the image: hardcoded passwords, private keys, enabled debug interfaces, weak random-number generation, and other known-bad patterns.

CVE lookup

Fingerprints the components and versions in the image and matches them against public CVE data (NVD). Every finding shows the basis for the match, so you can check it yourself.

Component inventory (SBOM)

Exports a component-fingerprint SBOM in CycloneDX or SPDX format — a starting point for the component inventory that customers and regulators increasingly ask for.

Readable HTML report

One report, in plain language: what was scanned, what was found, how serious it is, and what to do about it. Built to be read by a human, not just parsed by a machine.

Runs on Linux, Windows, and macOS

A one-click download with a ready-to-run binary for your system. No Python install, no virtual environment, no command-line toolchain to set up first.

What version 1 does not do

We would rather tell you plainly than let you find out after paying:

  • No filesystem extraction yet. Version 1 identifies compressed containers in an image (such as gzip or xz) but does not unpack them. Filesystem extraction is planned for a later version.
  • The SBOM is component-fingerprint based. Because version 1 does not unpack firmware, the SBOM lists the components the scanner can fingerprint from the image itself. It is not a full extracted-filesystem SBOM.
  • No emulation or dynamic analysis. Version 1 is a static scanner: it reads the image, it does not run it.
